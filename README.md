# Unfazed SaaS

Unfazed SaaS is a full-stack web application for managing a therapist's private practice from one platform.

It provides a **Therapist Dashboard** for managing clients, sessions, notes, payments, packages, communication, and analytics, along with a **Client Portal** for intake, consent, booking, payment, shared information, and communication.

---

* **GitHub Repository:** [View Source Code](https://github.com/divya-code-tech/unfazed-saas)

## Overview

The project was built to bring the main day-to-day workflows of a therapist's practice into a single application.

Instead of managing clients, appointments, notes, payments, and communication separately, Unfazed connects these workflows through a common frontend and backend.

The application is divided into two main experiences:

### Therapist Dashboard

The therapist's main workspace for managing the practice.

It includes:

* Dashboard
* Client management
* Scheduling and availability
* Clinical notes
* Payments and packages
* Analytics
* Real-time chat
* Therapist profile

### Client Portal

The client-facing side of the application.

It allows clients to:

* view the therapist's public profile
* complete intake information
* provide digital consent
* view available sessions
* book appointments
* make payments
* access information shared by the therapist
* view shared clinical notes
* communicate with the therapist

# Features

## Therapist Profile

Therapists can create and manage a public professional profile.

The profile includes information such as:

* therapist introduction
* about information
* specializations
* services
* booking availability

Each therapist has a unique public profile link that can be shared with clients.

---

## Client Management

The client management section works as the therapist's CRM.

It includes:

* client profiles
* search by name or email
* active/inactive filtering
* sorting by name
* sorting by last session
* client tags
* intake information
* presenting concern
* client history
* consent information
* session history
* payment history
* clinical notes

An individual client profile brings the relevant session, payment, and clinical information together for the therapist.

---

## Intake and Consent

The client intake flow collects information required before a session.

It supports information such as:

* client details
* presenting concern
* history
* languages
* other intake information

Digital consent is recorded with the consent status and timestamp. The timestamp is generated by the server so that it can be stored as an auditable record.

---

## Scheduling and Booking

The scheduling system manages therapist availability and client bookings.

Therapists can configure:

* recurring weekly availability
* one-time availability overrides
* blocked time periods
* session duration
* buffer time

The application supports 30, 45, 60, and 90-minute sessions.

The booking system also handles client-local timezone conversion and prevents a session slot from being booked twice.

---

## Payments and Packages

Razorpay is used for online payment processing.

The package system supports:

* 3-session packages
* 6-session packages
* 12-session packages

The payment workflow includes:

* payment records
* package management
* payment status
* session/payment relationships
* invoice generation
* Razorpay order handling

Payment-related logic is kept in dedicated backend services rather than being mixed into individual application routes.

---

## Clinical Documentation

Therapists can create and manage clinical notes for sessions.

The notes system supports:

* private therapist notes
* shared/client-visible notes
* rich-text editing
* session-based documentation

A key part of the implementation is the separation between private and shared clinical information.

Private notes are protected at the API level and are not returned by client-facing portal APIs.

The rich-text editor is implemented using Tiptap.

---

## Client Portal

The Client Portal provides a separate client-facing workflow.

A client can use it to:

* access the therapist's public profile
* complete intake
* provide consent
* book a session
* complete payment
* view available shared information
* access shared notes
* communicate with the therapist

Therapist-only information is kept separate from client-facing data.

---

## Real-Time Chat

The application includes therapist-client chat using Socket.IO.

Messages are exchanged in real time without requiring a full page refresh.

The implementation also handles connection state and maintains the conversation through the application backend.

---

## Notifications

A notification service is included for session and practice-related events.

The backend runs a scheduler that checks for notifications periodically and processes the required notification workflow.

Nodemailer is used for email-related notification handling.

---

# Subscription and Entitlements

Unfazed includes a subscription-based feature access system.

Subscription limits and feature flags are stored in the `SubscriptionTierConfig` collection.

The application uses a centralized entitlement service with:

```text
canAccess(therapistId, featureKey)
```

This keeps subscription checks in one place instead of checking tier names separately throughout the application.

The current subscription configuration is:

| Tier    | Clients | Sessions / Month | Packages | Analytics | Chat | Custom Branding |
| ------- | ------: | ---------------: | -------: | :-------: | :--: | :-------------: |
| Free    |       5 |               10 |        1 |     No    |  No  |        No       |
| Starter |      25 |               50 |        3 |    Yes    |  No  |        No       |
| Pro     |     100 |              200 |       10 |    Yes    |  Yes |       Yes       |
| Premium |     500 |             1000 |       50 |    Yes    |  Yes |       Yes       |

Feature access is applied to areas such as:

* analytics
* client creation
* package creation
* chat

When an action is not available on the current subscription, the backend can return an upgrade-required response and the frontend displays an upgrade prompt.

# Analytics

The therapist analytics dashboard provides practice-level information including:

* revenue trends
* active clients
* no-show rate
* session statistics

The main calculations are performed on the backend using MongoDB aggregation pipelines.

Recharts is used on the frontend to display the resulting data.

# Architecture

The project follows a three-layer full-stack structure.

### Frontend

The React/Vite frontend contains the Therapist Dashboard, Client Portal, authentication, scheduling, client management, payments, notes, chat, and analytics interfaces.

### Backend

The Node.js/Express backend provides the REST API and contains:

* routes
* controllers
* authentication middleware
* role-based access control
* database models
* business services
* entitlement checks
* payment services
* notification services
* Socket.IO communication

### Database

MongoDB is used as the main application database through Mongoose.

### External Services

The application integrates with:

* Razorpay for payments
* Socket.IO for real-time communication
* Nodemailer for email/notification handling

The external integrations are kept behind dedicated service areas so that application logic is not tightly coupled to a particular provider.

# Authentication and Security

The application uses:

* JWT-based authentication
* protected API routes
* role-based access control
* environment variables for sensitive configuration
* centralized entitlement checks
* API-level separation of private and shared clinical information
* rich-text sanitization

Private clinical notes are not exposed through client-facing portal APIs.

---

# Environment Configuration

The application uses environment variables for database connection, authentication, payment integration, and frontend/backend configuration.

The backend uses values such as:

```text
MONGO_URI
JWT_SECRET
RAZORPAY_KEY_ID
RAZORPAY_KEY_SECRET
CLIENT_URL
```

The frontend uses the configured API base URL:

```text
VITE_API_BASE_URL
```

Actual secret values and environment files are kept outside the repository and are not committed to GitHub.

# Running the Project Locally

## Prerequisites

Make sure the following are installed:

* Node.js
* npm
* MongoDB Atlas or MongoDB
* Git

For payment-related functionality, a Razorpay test account is also required.

---

## Clone the Repository

```bash
git clone https://github.com/divya-code-tech/unfazed-saas.git
cd unfazed-saas
```

---

## Start the Backend

Open a terminal and run:

```bash
cd unfazed-backend
npm install
node server.js
```

The backend requires the appropriate environment variables before it can connect to the database and external services.

---

## Start the Frontend

Open a second terminal:

```bash
cd unfazed-frontend
npm install
npm run dev
```

The frontend uses the configured backend API URL to communicate with the Express server.

---

# Deployment

The application is deployed as separate frontend and backend services.

* **Frontend:** Vercel
* **Backend/API:** Render
* **Database:** MongoDB Atlas

The frontend communicates with the backend through the configured API URL, while Socket.IO is used for real-time communication.
